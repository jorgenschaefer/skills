# Reviewers use different framings

`MANIFESTO.md`: "Reviewers use different framings, which reduces the blind
spots they share with the author but does not remove them."

The review after each build and the run's final review both run `critique`
against `CODING_STANDARDS.md` (`implement/SKILL.md:32`, `run/prompts.sh`
`review_brief`). The final review's brief adds the view between tickets -
the same thing built twice, one concept under two names - but critique
itself gets the same framing each time. The `VERIFY.md` files of `idea`,
`find-criteria` and `criteria-to-tickets` already differ by stage, and
`accept-criteria`'s subagent gets its own list of kinds.
